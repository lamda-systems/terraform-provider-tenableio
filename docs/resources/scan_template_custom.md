# tenableio_scan_template_custom (Resource)

Manages a user-defined scan template -- Scan Templates > User Defined in the Tenable.io UI, which the API calls a policy. Settings left out of the configuration keep the defaults of the Tenable-provided template it is based on, and are neither tracked nor changed. Removing a setting or a plugin family from the configuration replaces the template, because Tenable.io keeps any setting an update leaves out; set `create_before_destroy` if scans use it.

## Example Usage

```terraform
data "tenableio_policy_template_tenable" "advanced" {
  title = "Advanced Network Scan"
}

# A user-defined scan template. Only the settings written here are sent and
# tracked; everything else keeps the Advanced Network Scan defaults.
resource "tenableio_scan_template_custom" "internal" {
  template_uuid = data.tenableio_policy_template_tenable.advanced.uuid
  name          = "Internal - Baseline"
  description   = "Weekly baseline for the internal network"

  discovery {
    ping_the_remote_host = true
    portscan_range       = "1-65535"
    ssl_prob_ports       = "All ports"
  }

  assessment {
    override_accuracy = true
    report_paranoia   = "Avoid false alarms"
    thorough_tests    = true
  }

  report {
    reverse_lookup = true
  }

  advanced {
    safe_checks        = true
    max_hosts_per_scan = 30
  }

  plugin_family {
    name   = "Denial of Service"
    status = "disabled"
  }

  # Removing a setting or a plugin family replaces the template, which gives it
  # a new id. Create the replacement first so scans never point at nothing.
  lifecycle {
    create_before_destroy = true
  }
}

# An agent template takes the agent block; discovery does not apply to it.
data "tenableio_policy_template_tenable" "agent" {
  name = "agent_advanced"
}

resource "tenableio_scan_template_custom" "agents" {
  template_uuid = data.tenableio_policy_template_tenable.agent.uuid
  name          = "Agents - Baseline"

  agent {
    refresh_reporting_type           = "days"
    refresh_reporting_frequency_days = 14
    staggered_start_mins             = 30
  }
}

data "tenableio_scan_template_tenable" "advanced" {
  title = "Advanced Network Scan"
}

resource "tenableio_scan" "internal" {
  template_uuid = data.tenableio_scan_template_tenable.advanced.uuid
  policy_id     = tenableio_scan_template_custom.internal.id
  name          = "internal-weekly"
  text_targets  = "10.0.0.0/24"
}
```

## Settings

The `discovery`, `assessment`, `report`, `advanced` and `agent` blocks hold the
template's settings, typed and named as in the Tenable.io API reference for
[Create scan](https://developer.tenable.com/reference/scans-create) (a dot in an
API name becomes `_`, and each block's preconfigured mode is `mode`).

- **Only what you set is managed.** A setting left out keeps the default of the
  Tenable-provided template, is not sent, and is not tracked.
- **Removing a setting or a plugin family replaces the template.** Tenable.io keeps
  any setting an update leaves out, so it cannot be cleared in place. Replacement
  gives the template a new id; `create_before_destroy` keeps scans pointing at one.
- **Some settings are not reported back.** Tenable.io leaves out settings whose
  toggle is off (the web crawler settings while `assessment.scan_webapps` is off,
  for example). The apply then warns that those values cannot be verified, and a
  change made to them outside Terraform goes unnoticed.
- **The plan checks the template.** A uuid from the scan template list, a
  compliance template, or a setting documented only for the other kind of
  template (network or agent) fails the plan rather than being discarded.

## Import

```shell
terraform import tenableio_scan_template_custom.internal 45
```

An imported template starts with no settings tracked, so the first plan adds the
ones the configuration sets, in place.

## Migrating from `tenableio_policy`

Rename the resource and add a `moved` block. The template keeps its id and is not
recreated:

```terraform
resource "tenableio_scan_template_custom" "internal" {
  # ... the former tenableio_policy arguments, without visibility
}

moved {
  from = tenableio_policy.internal
  to   = tenableio_scan_template_custom.internal
}
```
